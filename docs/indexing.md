# Indexing Pipeline

The indexing pipeline is responsible for transforming the raw SEM dataset into a searchable representation stored in Qdrant.

The pipeline combines image embeddings with SEM metadata so that the resulting documents can be retrieved using both semantic similarity and metadata-based filtering.

> NOTE: right now, there are actually 2 indexing services, the first one composed of `upload/` and `pipeline_wrappers/indexing/`, which was a first test of a possible way of growing the knowledge database given a broader use-case, and the second one, which is the indexing system of the *static* SEM database, composed of `notebooks/embed.ipynb` and `src/sem_rag/qdrant_upload.py` (the one we will talk about).

## Overview

The indexing process can be summarized as:
```text
      SEM Dataset
          │
          ├── Images
          │
          ├── Metadata
          │
          ▼
   Data Processing
          │
     ┌────┴─────┐
     │          │
     ▼          ▼
Embeddings   Metadata
     │          │
     └────┬─────┘
          │
          ▼
   Haystack Documents
          │
          ▼
        Qdrant
```

The main stages are:
1. Load the dataset
2. Process the image data
3. Load or generate image embeddings
4. Process the associated metadata
5. Construct Haystack `Document` objects
6. Store the resulting documents in Qdrant

## Input Data

The indexing pipeline operates on SEM images together with their associated metadata.

The metadata contains acquisition and microscope parameters describing how each image was obtained. Examples include:
* Working distance
* Beam time
* Stage position
* Accelerating voltage
* Magnification-related parameters

These values are stored together with the corresponding image representation and are later used during retrieval.

## Image Embeddings

Each SEM image is represented by an embedding vector generated by an image embedding model.

InternRAG currently supports different embedding spaces for experimentation. In particular, Qwen-based and DINO-based embeddings have been explored.

Each embedding is associated with the corresponding SEM image through its image identifier.  
The embedding is used for vector similarity search in Qdrant.

## Metadata Processing

In addition to the image embedding, relevant SEM metadata is extracted and stored.  
Metadata fields are defined centrally in the project configuration.  
For example:
```text
AP_WD
AP_FREE_WD
AP_BEAM_TIME
AP_STAGE_LOW_Z
AP_STAGE_CENTRE_X
AP_C3
AP_EHT_CAL_30KV
AP_EHT_CAL_10KV
AP_EHT_CAL_100
AP_EHT_CAL_24KV
AP_MINMAG
```

Numeric metadata is stored in Qdrant as structured payload fields. This allows the retrieval pipeline to use metadata filters in addition to vector similarity.

## Haystack Documents

The processed information is represented using Haystack `Document` objects.  
A document contains:
* A unique identifier
* Textual content
* An embedding
* Metadata stored in the document payload

Conceptually, a document can be represented as:
```text
Document
├── id
├── content
├── embedding
└── meta
    ├── SEMImageID
    ├── AP_WD
    ├── AP_BEAM_TIME
    ├── ...
    └── other metadata
```

The textual content provides a human-readable representation of the indexed sample, while the embedding and metadata are used during retrieval.

## Qdrant

Qdrant is used as the vector database for the indexed SEM dataset.

The embedding is stored as the vector representation of the document, while metadata is stored as payload.

The project uses separate collections for different embedding spaces (e.g.: *SEMImages_dino*, *SEMImages_qwen*). This allows different embedding models to be evaluated independently without mixing vectors with incompatible dimensions or representations.

## Indexing Service

The indexing functionality is exposed through the indexing pipeline wrapper and can be deployed as an independent service.

The indexing service is responsible for executing the processing pipeline and writing the resulting documents to Qdrant.  
The Docker image used for this service is defined by `docker/Dockerfile.indexing` and the corresponding Kubernetes configuration is located under `k8s/indexing/`.

## Development and Experimentation

Several notebooks in the repository were used during the development of the indexing process.  
In particular, the notebooks under `notebooks/` contain experiments related to:
* Embedding generation
* Dataset inspection
* Qdrant uploads
* Testing different retrieval representations

These notebooks were used to validate the individual components before integrating them into the deployed pipeline.

## Result

After indexing, each SEM sample has a searchable representation consisting of:
```text
Image
  │
  ├── Embedding ────→ Vector search
  │
  └── Metadata ─────→ Metadata filtering
```

This representation forms the knowledge base used by the retrieval pipeline.
