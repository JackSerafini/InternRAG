# InternRAG

InternRAG is a Retrieval-Augmented Generation (RAG) system developed for the retrieval and analysis of **Scanning Electron Microscopy (SEM)** data. The project combines multimodal retrieval, metadata filtering, and Large Language Models (LLMs) to enable researchers to search and explore SEM datasets using both natural language and image queries.

The system indexes two static SEM image collections (the annotated **SEM** dataset and the **LAME** dataset) in Qdrant and exposes Haystack retrieval pipelines through Hayhooks as OpenAI-compatible "models" in Open WebUI.

## Features

* Text-to-image and image-to-image retrieval with the multimodal `Qwen/Qwen3-VL-Embedding-8B` embedding model
* LLM-based extraction of metadata constraints from the query (numeric ranges and categorical values), converted into Qdrant filters
* Diversity-aware re-ranking of candidates with Maximal Marginal Relevance (MMR)
* Candidate summaries generated by `google/gemma-4-26B-A4B-it`, with the retrieved thumbnails rendered inline in the chat
* Evaluation notebooks for text retrieval, image retrieval, metadata extraction and end-to-end behaviour
* Kubernetes deployment (Qdrant, Open WebUI, retrieval service)

# Architecture

InternRAG is organized into two parts:

### 1. Indexing (offline)

Run once per dataset from the scripts in `src/sem_rag/scripts/`:

* Load the image crops and parse their acquisition metadata (JSON for SEM, `.hdr` for LAME) into canonical fields
* Generate image embeddings with Qwen3-VL-Embedding-8B and a textual visual description of each image with a VLM
* Build Haystack `Document`s (text = metadata + visual description, payload = canonical metadata + thumbnail)
* Upload them to the dataset's Qdrant collection with indexed payload fields

See [`docs/indexing.md`](docs/indexing.md).

### 2. Retrieval (online)

For a text and/or image query, the retrieval service:

* Embeds the text or the image (if one is attached)
* Extracts explicit metadata constraints from the text with an LLM and turns them into Qdrant filters
* Retrieves the top 50 candidates from Qdrant and re-ranks them with MMR down to 5
* Asks the LLM to summarise each candidate (morphology + metadata) and appends the thumbnails

See [`docs/retrieval.md`](docs/retrieval.md).

# Installation

## Requirements

* Python 3.12
* [uv](https://docs.astral.sh/uv/)
* Access to the Orfeo vLLM gateway and to the project Qdrant instance (see [`docs/configuration.md`](docs/configuration.md))
* Docker and `kubectl` / Helm (only for deployment)

## Setup

```bash
uv sync
```

This installs the `sem_rag` package (from `src/`) and the dev dependency group.
Then create a `.env` file from `.env.example` (see [`docs/configuration.md`](docs/configuration.md)).

> [!NOTE]
> `requirements.txt` is a minimal list used mainly for Docker images and is not the source of truth for the local environment.

# Docker

Only the retrieval service has a Dockerfile (`docker/Dockerfile.retrieval`). The old indexing and upload images are archived in `archive/initial_rag/`.

```bash
docker buildx build \
    --platform linux/amd64 \
    -t your-dockerhub-user/rag-retrieval:latest \
    -f docker/Dockerfile.retrieval \
    --push .
```

Run it from the repository root. See [`docker/README.md`](docker/README.md).

# Kubernetes

Deployment manifests and Helm values are located in the `k8s/` directory.

The repository contains configurations for:

* Qdrant (Helm chart + ingress)
* Open WebUI (Helm chart + ingress)
* Retrieval service (Deployment + Service)
* Shared ConfigMap (`config.yaml`) and small debugging utilities (`net_debug/`, `hello_world/`)

Refer to [`k8s/README.md`](k8s/README.md) for deployment instructions.

# Notebooks

The `notebooks/` directory contains experiments and development utilities, including:

* Data preparation: `lame_images.ipynb` (LAME filtering/cropping), `embed.ipynb`, `qdrant_upload.ipynb`
* Analysis: `metadata_analysis.ipynb`, `qdrant_analysis.ipynb`, `descriptions_analysis.ipynb`, `retrieval_analysis.ipynb`, `test_data.ipynb`
* Evaluation: `EVAL_text_retrieval.ipynb`, `EVAL_image_retrieval.ipynb`, `EVAL_metadata_extraction.ipynb`, `EVAL_end2end.ipynb` (see [`docs/evaluation.md`](docs/evaluation.md))

These notebooks are intended for development and experimentation rather than production use.
